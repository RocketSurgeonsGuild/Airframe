# RSA2011: Declare accessibility explicitly

| Property | Value |
|-|-|
| **Rule ID** | RSA2011 |
| **Category** | Design |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes |
| **StyleCop equivalent** | SA1400 |

## Cause

A type or member relied on C#'s default accessibility instead of stating one.

## Rule description

Accessibility is stated rather than inferred from the C# default, so the declared surface of a type
is unambiguous to a reader who doesn't have the defaulting rules memorized (`private` for a class
member, `internal` for a top-level type, and so on).

## How to fix violations

Add the accessibility modifier the compiler would have inferred. The code fix does this — "Declare
'private' explicitly", "Declare 'internal' explicitly", and so on — and supports Fix All.

```csharp
// Violates RSA2011
class Sample
{
    string _name;
}
```

```csharp
// Satisfies RSA2011
private class Sample
{
    private string _name;
}
```

## When to suppress warnings

There is little reason to suppress this one broadly; it's a pure clarity rule with a safe,
mechanical fix. Suppress only where a codebase intentionally follows the terser default-accessibility
convention and isn't adopting RSA2011.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Design", "RSA2011:Declare accessibility explicitly", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA2011 // Declare an accessibility modifier for '{0}'
#pragma warning restore RSA2011
```

```ini
[*.cs]
dotnet_diagnostic.RSA2011.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README.
