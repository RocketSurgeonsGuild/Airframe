# RSA2014: Provide a summary for public abstractions

| Property | Value |
|-|-|
| **Rule ID** | RSA2014 |
| **Category** | Design |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | No |
| **StyleCop equivalent** | SA1600 (broader scope) |

## Cause

An interface declaration, an abstract type declaration, or one of the abstract/interface members
they declare has no XML documentation `<summary>`.

## Rule description

An interface or an abstract type declaration, and every member either of them declares without a
body — an interface member with no default implementation, or a member marked `abstract` in an
abstract class — is a contract other code is written against. RSA2014 requires a `<summary>` a
reader can act on without opening an implementation:

```csharp
/// <summary>Reads a value by key.</summary>
public interface IReader
{
    /// <summary>Gets the value for <paramref name="key"/>.</summary>
    string Read(string key);

    /// <summary>Parses <paramref name="value"/>.</summary>
    static abstract IReader Parse(string value);
}
```

A `static abstract` interface member (the generic-math pattern) is included: it has no body either,
so it is still part of the contract an implementer must fulfil.

**A default interface member and a concrete member of an abstract class are both excluded.**
Neither is part of the contract an implementer has to fulfil sight unseen, so RSA2014 leaves them
to whatever general documentation policy a project already runs. A default interface member stays
excluded whether or not it is `static`, since what excludes it is having a body, not being static.

## How to fix violations

Add a `<summary>` to the interface, abstract type, or abstract/interface member. There is no code
fix — the content of a summary is a judgment call only the author can make.

## When to suppress warnings

Suppress on a type or member whose contract is genuinely self-explanatory from its name and
signature alone, or where a project has a documentation policy this rule doesn't fit — for example,
an internal abstraction not part of any public surface.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Design", "RSA2014:Provide a summary for public abstractions", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA2014 // '{0}' has no XML documentation summary
#pragma warning restore RSA2014
```

```ini
[*.cs]
dotnet_diagnostic.RSA2014.severity = none
```
