# RSA1002: Provide a well-formed lambda expression for `BindTo`

| Property | Value |
|-|-|
| **Rule ID** | RSA1002 |
| **Category** | Usage |
| **Default severity** | Error |
| **Enabled by default** | Yes |
| **Code fix** | Yes |

## Cause

A `BindTo` call's target-property selector closed over an outer variable instead of being a pure
`x => x.Property` member access.

## Rule description

`BindTo(this, x => x.Value)` works by reading `x.Value`'s property expression at compile time to
resolve the setter — it does not execute the lambda body against an arbitrary object graph. Writing
`x => Value` (closing over `this` instead of using the lambda parameter) compiles but resolves the
wrong member, or throws at runtime depending on the overload picked. RSA1002 flags a lambda whose
body is not a simple member access rooted at the parameter.

## How to fix violations

Write the selector as `x => x.Member`, using the lambda parameter rather than an outer closure.

```csharp
// Violates RSA1002
Observable
   .Return(Unit.Default)
   .BindTo(this, x => Value);
```

```csharp
// Satisfies RSA1002
Observable
   .Return(Unit.Default)
   .BindTo(this, x => x.Value);
```

## When to suppress warnings

Don't. RSA1002 reports a default severity of `Error` because the flagged shape is usually a runtime
bug, not a style preference — suppressing it hides a call that resolves the wrong member.

## Suppress a warning

```csharp
#pragma warning disable RSA1002 // Unsupported expression type.
#pragma warning restore RSA1002
```

```ini
[*.cs]
dotnet_diagnostic.RSA1002.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README for the
`SuppressMessageAttribute` form and when to prefer it over `.editorconfig`.
