# RSA0009: Do not declare a nullable reference return type on an abstraction member

| Property | Value |
|-|-|
| **Rule ID** | RSA0009 |
| **Category** | Nullability |
| **Default severity** | Info |
| **Enabled by default** | No |
| **Code fix** | No |

## Cause

An abstract, virtual, or interface method or property - including a default interface member with
a body, and a `static abstract` interface member - declares a nullable reference return type.

## Rule description

An abstract, virtual, or interface member originates a contract: every override and every
implementation inherits its declared nullability, whether or not that was the right call for all of
them. Neither RSA2014 nor the compiler's own nullable reference type analysis evaluates the
abstraction itself - both stop at "does the implementation match what the abstraction declared."

```csharp
// Violates RSA0009
public interface IReader
{
    string? Read();
}
```

**A collection-shaped or task-shaped return type is excluded**, since [RSA0002](RSA0002.md) and
[RSA0003](RSA0003.md) already report those at `Warning` severity; this rule covers everything
else - a nullable `string`, a nullable domain type, and so on.

**An override, and a member that is neither `abstract` nor `virtual`** (a sealed default interface
member, an explicit interface implementation, a plain concrete member) **are not the origin of the
contract and are not reported** - only the abstract, virtual, or interface declaration that
introduced the nullable return type is.

**Ships disabled by default.** Locating a layer boundary where a nullable abstraction is genuinely
the wrong call - as opposed to a domain that legitimately models "no result" through the return
type of its own contract - requires project-specific judgment this analyzer cannot make on its own.
Enable it deliberately once a codebase's abstractions are being reviewed for this.

## How to fix violations

Model "no result" in the abstraction's implementations instead of in the contract - for example, an
`Optional<T>`/`Result<T>`-shaped return, a `TryRead`-style `bool` overload, or splitting the
abstraction so the nullable case has its own named member.

## When to suppress warnings

Suppress for an abstraction that intentionally documents "may return nothing" as part of its
contract, where every implementor is expected to handle that and a non-nullable alternative would
just relocate the null-check rather than remove it.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Nullability", "RSA0009:Do not declare a nullable reference return type on an abstraction member", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA0009 // '{0}' is abstract, virtual, or an interface member; its nullable reference return type is forced onto every override and implementation
#pragma warning restore RSA0009
```

```ini
[*.cs]
dotnet_diagnostic.RSA0009.severity = suggestion
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README for the
`SuppressMessageAttribute` form and when to prefer it over `.editorconfig`.
