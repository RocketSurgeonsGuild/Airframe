# RSA3001: Subscription not disposed

| Property | Value |
|-|-|
| **Rule ID** | RSA3001 |
| **Category** | Performance |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes |

## Cause

The `IDisposable` returned by `Subscribe`, `BindTo`, `InvokeCommand`, or `ToProperty` was not
disposed.

## Rule description

Every one of those calls returns a subscription that must be disposed, or the underlying observable
keeps a reference to its subscriber for as long as the source lives — a classic ReactiveUI/Rx
leak, especially inside a `ReactiveObject` whose lifetime is shorter than the observable it
subscribed to.

```csharp
Observable
   .Return(Unit.Default)
   .Subscribe(); // leaks: nothing disposes this
```

RSA3001 matches these method names exactly, not by substring — a call to `SafeSubscribe`,
`SubscribeSafe`, or `Bind` (as opposed to `BindTo`) is not flagged.

## How to fix violations

Chain `.DisposeWith(...)` onto a `CompositeDisposable` the containing type tears down (its
`Garbage`/`ViewModelActivator` disposable, or an equivalent field), or otherwise store and dispose
the subscription explicitly.

```csharp
// Satisfies RSA3001
Observable
   .Return(Unit.Default)
   .Subscribe()
   .DisposeWith(Garbage);
```

The code fix inserts `.DisposeWith(...)` for you, prompting for the disposable to target.

## When to suppress warnings

Suppress where the subscription is intentionally fire-and-forget for the lifetime of the process
(a static, app-lifetime subscription with nothing shorter-lived to tie it to). Justify that
explicitly — it is easy to be wrong about a type's real lifetime.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Performance", "RSA3001:Subscription not disposed", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA3001 // Consider use of DisposeWith to clean up subscriptions
#pragma warning restore RSA3001
```

```ini
[*.cs]
dotnet_diagnostic.RSA3001.severity = none
```
