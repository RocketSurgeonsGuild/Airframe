# RSA2010: Do not use regions

| Property | Value |
|-|-|
| **Rule ID** | RSA2010 |
| **Category** | Design |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes |
| **StyleCop equivalent** | SA1124 |

## Cause

A `#region`/`#endregion` directive was present in the file.

## Rule description

Regions hide code rather than organize it, and a region directive travels with the member below it
— which is exactly the ambiguity that makes the RSA2XXX ordering rules harder to reason about
around directives in general (see RSA2012 for the related conditional-compilation case).

## How to fix violations

Remove the region directive. The code fix does this for you; it is "Remove the region" in your
IDE's light bulb, and supports Fix All.

## When to suppress warnings

Suppress on a large, pre-existing file you are not yet ready to restructure, where removing the
region without also splitting the file would make navigation worse, not better.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Design", "RSA2010:Do not use regions", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA2010 // Remove the region directive
#pragma warning restore RSA2010
```

```ini
[*.cs]
dotnet_diagnostic.RSA2010.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README.

## Running alongside StyleCop

RSA2010 replaces SA1124. See [Running alongside StyleCop](../README.md#running-alongside-stylecop).
