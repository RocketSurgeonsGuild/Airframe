# RSA2001: Constructors should appear before other members

| Property | Value |
|-|-|
| **Rule ID** | RSA2001 |
| **Category** | Design |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes (shared ordering fix; see [Using the ordering fix as a formatter](../README.md#using-the-ordering-fix-as-a-formatter)) |
| **StyleCop equivalent** | None — SA1201 requires the opposite order |

## Cause

A constructor or destructor was declared after another member instead of leading the type.

## Rule description

Constructors and destructors are declared first, whatever their accessibility, so the ways a type
can be created lead the file. This is one of the seven RSA2XXX [member-ordering rules](../README.md#member-ordering);
each rule owns one component of the comparison, so a misplaced member reports against exactly one
rule. RSA2001 never applies to interfaces or enumerations, whose members declare no accessibility.

## How to fix violations

Move the constructor (or destructor) above the members that currently precede it, or run the shared
ordering code fix, which supports Fix All:

```bash
dotnet format analyzers --diagnostics RSA2001,RSA2002,RSA2003,RSA2004,RSA2005,RSA2006,RSA2007
```

The fix applies the whole layout at once — see
[Using the ordering fix as a formatter](../README.md#using-the-ordering-fix-as-a-formatter) for what
it will and won't touch (it declines when a directive's meaning depends on where it sits among the
members).

## When to suppress warnings

Suppress on a type whose member order is fixed by something outside your control — a partial class
whose other half a source generator owns, for instance — rather than one you can simply reorder.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Design", "RSA2001:Constructors should appear before other members", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA2001 // Constructors should appear before other members
#pragma warning restore RSA2001
```

```ini
[*.cs]
dotnet_diagnostic.RSA2001.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README for when to reach
for the attribute versus `.editorconfig`, and why `Justification` matters.

## Running alongside StyleCop

RSA2001 has no StyleCop counterpart and requires the opposite order from SA1201, so SA1201 must be
`none` for RSA2001 to be satisfiable at all. See
[Running alongside StyleCop](../README.md#running-alongside-stylecop).
