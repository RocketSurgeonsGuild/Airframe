# RSA2005: Static members should appear before instance members

| Property | Value |
|-|-|
| **Rule ID** | RSA2005 |
| **Category** | Design |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes (shared ordering fix) |
| **StyleCop equivalent** | SA1204 |

## Cause

Within a kind and accessibility, a static member was declared after an instance member.

## Rule description

Within a kind and accessibility, static members are declared before instance members. This is one
of the seven RSA2XXX [member-ordering rules](../README.md#member-ordering). RSA2005 never applies
to interfaces or enumerations.

## How to fix violations

Move static members above instance members of the same kind and accessibility, or run the shared
ordering fix (supports Fix All):

```bash
dotnet format analyzers --diagnostics RSA2001,RSA2002,RSA2003,RSA2004,RSA2005,RSA2006,RSA2007
```

## When to suppress warnings

If you already use StyleCop's SA1204 and are not ready to retire it in favor of RSA2005, suppress
one or the other, not both — see [Running alongside StyleCop](../README.md#running-alongside-stylecop).

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Design", "RSA2005:Static members should appear before instance members", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA2005 // Static members should appear before instance members
#pragma warning restore RSA2005
```

```ini
[*.cs]
dotnet_diagnostic.RSA2005.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README.
