# RSA2004: Members should be ordered by access

| Property | Value |
|-|-|
| **Rule ID** | RSA2004 |
| **Category** | Design |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes (shared ordering fix) |
| **StyleCop equivalent** | SA1202 |

## Cause

Within a kind, members were declared out of access order.

## Rule description

Within a kind, members are declared in the order public, internal, protected internal, protected,
private protected, private. This is one of the seven RSA2XXX
[member-ordering rules](../README.md#member-ordering). RSA2004 never applies to interfaces or
enumerations, whose members declare no accessibility.

## How to fix violations

Reorder the members to match the access sequence above, or run the shared ordering fix (supports
Fix All):

```bash
dotnet format analyzers --diagnostics RSA2001,RSA2002,RSA2003,RSA2004,RSA2005,RSA2006,RSA2007
```

Note that turning RSA2004 off only stops it being reported — invoking the shared fix for any of the
other six rules still reorders by access. See
[Using the ordering fix as a formatter](../README.md#using-the-ordering-fix-as-a-formatter).

## When to suppress warnings

If you already use StyleCop's SA1202 and are not ready to retire it in favor of RSA2004, suppress
one or the other, not both — see [Running alongside StyleCop](../README.md#running-alongside-stylecop).

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Design", "RSA2004:Members should be ordered by access", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA2004 // Members should be ordered by access
#pragma warning restore RSA2004
```

```ini
[*.cs]
dotnet_diagnostic.RSA2004.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README.
