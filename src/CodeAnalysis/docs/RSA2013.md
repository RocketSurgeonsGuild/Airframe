# RSA2013: Line exceeds the maximum length

| Property | Value |
|-|-|
| **Rule ID** | RSA2013 |
| **Category** | Design |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes ("chop line") |
| **StyleCop equivalent** | None |

## Cause

A line was longer than the `max_line_length` `.editorconfig` key.

## Rule description

RSA2013 reports any line whose **code content** exceeds the margin. The limit comes from the
`max_line_length` editorconfig key, the same key Rider and ReSharper read, so the margin the editor
draws and the margin the build enforces are one number. **Where that key is absent, or set to
`off`, the rule reports nothing** rather than inventing a limit:

```ini
[*.cs]
max_line_length = 160
```

A line's code content excludes any trailing run of comment or XML documentation-comment trivia,
and the whitespace leading into it. Practically:

- A line that is entirely comment — a `//` line, an XML doc (`///`) line, or an interior line of a
  `/* */` block — has no code content and is never reported, no matter how long.
- A short declaration with a long trailing `// comment` is measured by the declaration alone; the
  comment does not count toward the margin.
- The reported length is always the code content length, not the raw line length, so appending a
  comment can never be used to silence a line whose code is genuinely too long — only its own code
  is ever shortened to make the line comply.
- A comment that appears *before* code on the same line (`foo(/* x */ bar);`) is not trailing, so
  it does not shrink the measured length; only a comment run that reaches the end of the line is
  excluded.
- This carve-out is for comment *trivia* specifically. Text that merely looks like a comment
  because it sits inside an inactive `#if`/`#endif` region is disabled-text, not comment trivia, so
  it is measured and reported like any other line in that state.

## How to fix violations

Run the code fix, the equivalent of Rider's chop line. It breaks the outermost construct on the
line that can carry a break:

| Construct | Result |
|-----------|--------|
| Parameter list | one parameter per line |
| Argument list | one argument per line |
| Collection expression and object initializer | one element per line |
| Expression body | break after the arrow |

```csharp
public static string Combine(string first, string second, string third, string fourth)
```

becomes

```csharp
public static string Combine(
    string first,
    string second,
    string third,
    string fourth)
```

**Roslyn's formatter does not wrap** — `dotnet format` alone will never shorten a line, which is why
this fix exists. **One chop per pass**: a line long enough to need two breaks shortens on the first
pass and is reported again on the next, so repeated runs converge. Nothing is offered for a line
whose length is a string literal or a comment, since there is no break to insert that wouldn't
change the text.

## When to suppress warnings

Suppress on a line that is long because it is a string literal, URL, or generated signature that
cannot be wrapped without changing its meaning — the code fix already declines those, so a
suppression there is documenting the same fact for the analyzer. Comments and XML documentation no
longer need suppression: they are excluded from the measured length outright, so they are not
reported in the first place.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Design", "RSA2013:Line exceeds the maximum length", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA2013 // Line is {0} characters long; the maximum is {1}
#pragma warning restore RSA2013
```

```ini
[*.cs]
dotnet_diagnostic.RSA2013.severity = none
```
