# RSA2002: Private members should appear after non-private members

| Property | Value |
|-|-|
| **Rule ID** | RSA2002 |
| **Category** | Design |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes (shared ordering fix) |
| **StyleCop equivalent** | None |

## Cause

A `private` member was declared before a non-private member of the same kind.

## Rule description

A type's public surface is declared before its implementation details, so a reader meets the
contract before the machinery. This is one of the seven RSA2XXX [member-ordering rules](../README.md#member-ordering).
RSA2002 never applies to interfaces or enumerations, whose members declare no accessibility.

## How to fix violations

Move private members below every non-private member of the same kind, or run the shared ordering
fix (supports Fix All):

```bash
dotnet format analyzers --diagnostics RSA2001,RSA2002,RSA2003,RSA2004,RSA2005,RSA2006,RSA2007
```

## When to suppress warnings

Suppress only where an external convention (a generated partial, a framework base-class contract)
already fixes the order and reordering would fight it.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Design", "RSA2002:Private members should appear after non-private members", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA2002 // Private members should appear after non-private members
#pragma warning restore RSA2002
```

```ini
[*.cs]
dotnet_diagnostic.RSA2002.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README.
