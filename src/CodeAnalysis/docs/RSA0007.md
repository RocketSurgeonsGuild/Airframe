# RSA0007: Use null instead of default for a nullable reference type

| Property | Value |
|-|-|
| **Rule ID** | RSA0007 |
| **Category** | Nullability |
| **Default severity** | Info |
| **Enabled by default** | Yes |
| **Code fix** | No |

## Cause

A `default` literal or a `default(T)` expression targets a nullable reference type - a parameter
default, a field or property initializer, a return, a local, an assignment, an argument, or a
generic context resolved to a nullable reference type.

## Rule description

`default` and `default(T)` evaluate to `null` for any reference type, but the keyword also means
something entirely different for a value type - a real, non-null, zeroed value. Using it for a
reference type borrows a keyword whose meaning changes depending on what it's applied to, when
`null` already says exactly what is meant and means only that:

```csharp
// Violates RSA0007
public string? Read(string? value = default) => default;
```

```csharp
// Satisfies RSA0007
public string? Read(string? value = null) => null;
```

**A value-typed target, and an unconstrained generic type parameter, are excluded.** `default` for
`int`, for `bool`, or for a `T` with no `class` constraint is not disguising `null` - it is
producing that type's genuine zero value, which is exactly what `default` is for. A generic type
parameter constrained to `class` is a reference type, and `default` targeting it is included, the
same as any other reference type.

**A `default` suppressed with the null-forgiving operator against a non-nullable target** (e.g.
`private string _value = default!;`) **is not reported**, since the target there is not itself a
nullable reference type - the `!` is doing something else entirely (silencing a constructor
initialization warning), which is not this rule's concern.

Adjacent to the built-in IDE0034 (simplify `default(T)` to `default`), which only simplifies syntax
between the two forms of `default` and never suggests `null`; the two converge on `null` for a
reference-typed target rather than conflicting with each other.

## How to fix violations

Replace `default` or `default(T)` with `null` wherever the target is a nullable reference type.

## When to suppress warnings

Suppress where `default` is used generically across both reference and value type instantiations
in a way a per-call-site `null` would not clearly express - for example, a generic helper that is
also exercised with value type arguments, where `default` reads as the single consistent choice
across all of them.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Nullability", "RSA0007:Use null instead of default for a nullable reference type", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA0007 // This targets '{0}', a nullable reference type; use 'null' instead of 'default'
#pragma warning restore RSA0007
```

```ini
[*.cs]
dotnet_diagnostic.RSA0007.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README for the
`SuppressMessageAttribute` form and when to prefer it over `.editorconfig`.
