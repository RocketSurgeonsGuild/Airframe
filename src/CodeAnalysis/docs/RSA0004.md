# RSA0004: Null-forgiving operator used too many times in one member

| Property | Value |
|-|-|
| **Rule ID** | RSA0004 |
| **Category** | Nullability |
| **Default severity** | Info |
| **Enabled by default** | Yes |
| **Code fix** | No |

## Cause

A method, constructor, or property declaration uses the null-forgiving operator (`!`) more than
the configured threshold - three, by default - within its own body or expression body.

## Rule description

The null-forgiving operator overrides the compiler's nullable flow analysis one expression at a
time: "you think this might be null; I know better." No single use is wrong on its own - that is
exactly what the operator is for. Density is the signal RSA0004 looks for instead: a member that
leans on it repeatedly is very often suppressing a design defect - a constructor that should
validate its arguments, a property that should not have been nullable in the first place - rather
than fixing it.

```csharp
// Violates RSA0004 (four uses in one member)
public string Combine(string? a, string? b, string? c, string? d) => a! + b! + c! + d!;
```

A null-forgiving operator inside a local function or lambda declared within the member counts
toward that member's total rather than being tracked separately - the density this rule cares
about is per author unit of code, not per syntactic scope.

**A `!` immediately to the left of `is` or an `is` pattern is not counted** - `x! is string` behaves
identically to `x is string`, since a type test ignores nullability entirely. That specific shape is
already reported individually by the built-in [IDE0080](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/style-rules/ide0080)
("Remove unnecessary suppression operator"), confirmed by inspecting its decompiled implementation:
it registers only on `is` and `is`-pattern expressions, and fires only when their left-hand side is
a suppression. Every other `!` site is outside IDE0080's registration entirely, so this rule's
density count and IDE0080's per-site check do not otherwise overlap - density can be real with zero
IDE0080 hits, and an IDE0080 hit can exist on a member nowhere near the density threshold.

## How to fix violations

There is no mechanical fix. Look at why the compiler doesn't already know these values are safe:
a missing argument-null guard, a property that should be `required` or non-nullable, a return type
that should not have been declared nullable in the first place. Fixing the root cause removes the
need for the suppression; only fix the individual suppression once you've confirmed it's still
genuinely necessary after that.

## When to suppress warnings

Suppress on a member where every use is independently justified and no design change would remove
the need for any of them - for example, a member that bridges into an unannotated third-party API
at several points, each of which is checked in some way the compiler can't see.

## Configuration

The threshold defaults to 3. Configure it with a custom `.editorconfig` key:

```ini
[*.cs]
rsa0004_max_null_forgiving_operators = 5
```

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Nullability", "RSA0004:Null-forgiving operator used too many times in one member", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA0004 // '{0}' uses the null-forgiving operator (!) {1} times; more than {2} in a single member suggests a suppressed design defect rather than a fix
#pragma warning restore RSA0004
```

```ini
[*.cs]
dotnet_diagnostic.RSA0004.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README for the
`SuppressMessageAttribute` form and when to prefer it over `.editorconfig`.
