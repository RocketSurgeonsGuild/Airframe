# RSA1005: Specify a scheduler for better control over execution timing

| Property | Value |
|-|-|
| **Rule ID** | RSA1005 |
| **Category** | Usage |
| **Default severity** | Suggestion |
| **Enabled by default** | Yes |
| **Code fix** | Yes |

## Cause

A Reactive Extensions or DynamicData operator with an `IScheduler` overload was called without
providing a scheduler, and no scheduler was reachable through the call chain.

## Rule description

Operators such as `Batch`, `BatchIf`, and `BufferInitial` accept an optional `IScheduler`. Left
unspecified, they fall back to a default scheduler that varies by platform and is not swappable in
tests. Passing the scheduler explicitly makes execution timing predictable and lets a test
substitute `TestScheduler` or `ImmediateScheduler`.

## How to fix violations

Pass an explicit scheduler argument to the overload that accepts one.

```csharp
// Violates RSA1005
changes
   .Connect()
   .Batch(TimeSpan.FromSeconds(1))
   .Subscribe();
```

```csharp
// Satisfies RSA1005
changes
   .Connect()
   .Batch(TimeSpan.FromSeconds(1), scheduler)
   .Subscribe();
```

## When to suppress warnings

Suppress at a call site where the default scheduler is intentional and the pipeline is not under
test, or where introducing a scheduler parameter would require threading one through a type that
has no other reason to take one. This rule reports at `Suggestion` severity for that reason — it is
signal, not a mandate.

## Suppress a warning

```csharp
#pragma warning disable RSA1005 // Consider specifying a scheduler for better control over execution timing
#pragma warning restore RSA1005
```

```ini
[*.cs]
dotnet_diagnostic.RSA1005.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README for the
`SuppressMessageAttribute` form and when to prefer it over `.editorconfig`.
