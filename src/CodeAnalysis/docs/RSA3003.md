# RSA3003: Lambda expression captures state and allocates a closure

| Property | Value |
|-|-|
| **Rule ID** | RSA3003 |
| **Category** | Performance |
| **Default severity** | Suggestion |
| **Enabled by default** | Yes |
| **Code fix** | No |

## Cause

A lambda passed to an Rx/DynamicData operator (`Select`, `Where`, `Subscribe`, `WhenAnyValue`,
`Filter`, `AutoRefresh`, a `ReactiveCommand` factory, and similar) captured a local variable, a
parameter, or instance state — including an implicit reference to `this` through an unqualified
instance member access.

## Rule description

A lambda that captures anything from its enclosing scope allocates a closure object on every
invocation site that creates it, to hold the captured state alive for as long as the lambda is
reachable. Capturing `this` implicitly is easy to miss, because no `this.` qualifier appears in
the source — an unqualified reference to an instance field, property, or method inside the lambda
is enough. RSA3003 is the informational counterpart to RSA3002: RSA3002 fires only when a lambda
could be marked `static` (source implicitly proving no capture); RSA3003 instead observes an
actual capture directly, through the same data-flow analysis that data flow reports for both a
captured local/parameter and an implicit `this`.

## How to fix violations

There usually isn't one fix — a lambda that needs the captured state to do its job is meant to
capture it. Where the capture isn't actually necessary, remove the dependency on outer state (pass
what's needed as a parameter instead, or hoist a pure computation to a `static` lambda/method).

```csharp
// Violates RSA3003 — captures the instance through an implicit 'this'
public class Watcher
{
    private readonly string _prefix;

    public Watcher(IObservable<string> source, string prefix)
    {
        _prefix = prefix;
        source.Select(value => _prefix + value).Subscribe();
    }
}
```

```csharp
// Satisfies RSA3003 — the prefix is captured explicitly as a local, or the lambda takes
// only what a static, non-capturing lambda needs
public class Watcher
{
    public Watcher(IObservable<string> source, string prefix)
    {
        source.Select(static (value, state) => state + value, prefix).Subscribe();
    }
}
```

## When to suppress warnings

RSA3003 is informational — it exists so a reader can see, at a glance, which lambdas allocate and
decide whether that's acceptable for the call site (a one-time setup subscription is a very
different cost than a lambda invoked per item in a hot `Select`). Suppress where the capture is
intentional and the allocation cost doesn't matter for that call site.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Performance", "RSA3003:Lambda expression captures state and allocates a closure", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA3003 // Lambda expression captures state and allocates a closure
#pragma warning restore RSA3003
```

```ini
[*.cs]
dotnet_diagnostic.RSA3003.severity = none
```
