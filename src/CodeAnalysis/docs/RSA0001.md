# RSA0001: Do not expose a plain setter on a non-nullable reference type auto-property

| Property | Value |
|-|-|
| **Rule ID** | RSA0001 |
| **Category** | Nullability |
| **Default severity** | Info |
| **Enabled by default** | Yes |
| **Code fix** | No |

## Cause

A public or protected auto-property of non-nullable reference type has a plain `set` accessor.

## Rule description

CS8618 checks only that a constructor exits with every non-nullable property assigned a non-null
value - it never checks what happens afterward. A plain `set` leaves the door open indefinitely: any
external caller can reassign the property to `null` at any point after construction, and nothing
stops them:

```csharp
// Violates RSA0001
public class Order
{
    public Order(string customerName) => CustomerName = customerName;

    public string CustomerName { get; set; }
}
```

```csharp
// Satisfies RSA0001
public class Order
{
    public Order(string customerName) => CustomerName = customerName;

    public string CustomerName { get; init; }
}
```

**A narrowed setter is excluded.** `private set` and `internal set` are not reported: external code
was never able to reach them, so the concern this rule targets doesn't apply.

**A property with a hand-written accessor body is excluded**, since a manual setter may already
guard against `null` itself - RSA0001 only targets the auto-property shape, where there is nowhere
for such a guard to live.

**An override and an explicit interface implementation are excluded.** Neither author chose that
member's mutability - the abstract or interface declaration that originated the plain `set` is
where RSA0001 reports instead.

**A property on a type that implements `INotifyPropertyChanged`, or one carrying a `[Reactive]`
attribute (matched by name, regardless of namespace - the ReactiveUI.Fody and
ReactiveUI.SourceGenerators ones both included), is excluded.** A bindable view-model property is
expected to be externally mutable by design - the binding infrastructure, not just the type's own
constructor, is what assigns it.

## How to fix violations

Change the setter to `init` (or `required init`, if construction must supply a value). Where the
type is a plain data holder rather than a class that needs identity, converting it to a `record`
with positional parameters is usually the larger, more thorough fix.

## When to suppress warnings

Suppress on a property that is intentionally mutable after construction for a reason this analyzer
can't see - a builder-style API, a POCO deserialized and then mutated in place by a framework this
analyzer doesn't recognize as bindable.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Nullability", "RSA0001:Do not expose a plain setter on a non-nullable reference type auto-property", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA0001 // '{0}' is a non-nullable reference type auto-property with a public setter; use 'init' or a positional record parameter instead
#pragma warning restore RSA0001
```

```ini
[*.cs]
dotnet_diagnostic.RSA0001.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README for the
`SuppressMessageAttribute` form and when to prefer it over `.editorconfig`.
