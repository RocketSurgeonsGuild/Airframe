# RSA2008: File should contain a single type

| Property | Value |
|-|-|
| **Rule ID** | RSA2008 |
| **Category** | Design |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | No |
| **StyleCop equivalent** | SA1402 |

## Cause

A file declared more than one top-level type.

## Rule description

A file declares one top level type, so a type can be found from its file name alone. RSA2008
accepts types that share a name — `IListener` beside `IListener<T>` is not a violation, since they
are the same logical member from a file-naming standpoint.

## How to fix violations

Move each additional top-level type to its own file. There is no code fix — splitting a file is a
structural change RSA2008 leaves to you (and to `RSA2009`, which will then check the new file's
name).

## When to suppress warnings

Suppress on a file that intentionally groups small, tightly-coupled types (a type and its private
nested-visibility companion that isn't literally nested, for example) where splitting would hurt
more than it helps.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Design", "RSA2008:File should contain a single type", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA2008 // Move '{0}' to its own file
#pragma warning restore RSA2008
```

```ini
[*.cs]
dotnet_diagnostic.RSA2008.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README.

## Running alongside StyleCop

RSA2008 replaces SA1402. See [Running alongside StyleCop](../README.md#running-alongside-stylecop).
