# RSA1010: Bind DynamicData changesets on the UI thread

| Property | Value |
|-|-|
| **Rule ID** | RSA1010 |
| **Category** | Usage |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | No |

## Cause

A DynamicData `.Bind(...)` call is not preceded, anywhere earlier in its fluent chain, by an
`.ObserveOn(...)` call.

## Rule description

`Bind` writes changeset updates directly into the target collection, and that collection is very
often data-bound to a UI element. If the changeset stream isn't observed on the UI thread before
`Bind` runs, those writes happen on whatever thread the upstream source produces notifications on
-- frequently a background thread -- which a UI framework will reject or silently corrupt.
`ObserveOn` makes the thread the updates land on an explicit, reviewable part of the pipeline
rather than an assumption about where the source happens to run.

RSA1010 recognizes an `ObserveOn` call anywhere earlier in the same fluent chain, including one
reached by following a local variable back to its own initializer (so a chain split across a
statement boundary is still recognized). It does not perform general dataflow analysis: a variable
reassigned after declaration, a value that arrives via a method parameter, or a value returned from
a helper method is not tracked, so RSA1010 may still (rarely) miss a preceding `ObserveOn` for those
shapes.

## How to fix violations

Add an `.ObserveOn(...)` call earlier in the chain, before `.Bind(...)`.

```csharp
// Violates RSA1010
cache
   .Connect()
   .Bind(out var items)
   .Subscribe();
```

```csharp
// Satisfies RSA1010
cache
   .Connect()
   .ObserveOn(RxApp.MainThreadScheduler)
   .Bind(out var items)
   .Subscribe();
```

## When to suppress warnings

Suppress where the changeset stream is already guaranteed to be observed on the UI thread before
this `Bind` call runs through a shape RSA1010 doesn't recognize (for example, a value arriving via a
method parameter that is already `ObserveOn`'d by its caller).

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Usage", "RSA1010:Bind DynamicData changesets on the UI thread", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA1010 // Bind DynamicData changesets on the UI thread
#pragma warning restore RSA1010
```

```ini
[*.cs]
dotnet_diagnostic.RSA1010.severity = none
```
