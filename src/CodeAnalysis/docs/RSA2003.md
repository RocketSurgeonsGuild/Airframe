# RSA2003: Members should be ordered by kind

| Property | Value |
|-|-|
| **Rule ID** | RSA2003 |
| **Category** | Design |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes (shared ordering fix) |
| **StyleCop equivalent** | SA1201 |

## Cause

Within a group, members were declared out of kind order.

## Rule description

Within a group, members are declared in the order fields, events, properties, indexers, methods,
operators, nested types. Within the private group specifically, fields sink below every other kind
instead of leading it, since a private field is implementation detail backing the members above it.
This is one of the seven RSA2XXX [member-ordering rules](../README.md#member-ordering). RSA2003
never applies to interfaces or enumerations.

## How to fix violations

Reorder the members to match the kind sequence above, or run the shared ordering fix (supports Fix
All):

```bash
dotnet format analyzers --diagnostics RSA2001,RSA2002,RSA2003,RSA2004,RSA2005,RSA2006,RSA2007
```

## When to suppress warnings

If you already use StyleCop's SA1201 for this and are not ready to retire it in favor of RSA2003,
suppress RSA2003 (or SA1201, but not both — see
[Running alongside StyleCop](../README.md#running-alongside-stylecop)) rather than get duplicate
diagnostics.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Design", "RSA2003:Members should be ordered by kind", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA2003 // Members should be ordered by kind
#pragma warning restore RSA2003
```

```ini
[*.cs]
dotnet_diagnostic.RSA2003.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README.
