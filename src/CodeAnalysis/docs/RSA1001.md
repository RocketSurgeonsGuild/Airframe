# RSA1001: Use expression lambda overload for `InvokeCommand`

| Property | Value |
|-|-|
| **Rule ID** | RSA1001 |
| **Category** | Usage |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes |

## Cause

`InvokeCommand` was called with a bare `this.Command` member-access argument instead of a
`this, x => x.Command` expression-lambda overload.

## Rule description

ReactiveUI's `InvokeCommand` has two overloads: one takes the `ICommand`/`ReactiveCommand` instance
directly, the other takes a source object and an expression selecting the command property from it
(`observable.InvokeCommand(this, x => x.Command)`). The expression-lambda overload lets ReactiveUI
re-resolve the command each time it changes and gives better `WhenActivated` and design-time
behavior. Passing the command instance directly bypasses that.

## How to fix violations

Change the argument to the two-argument, expression-lambda form.

```csharp
// Violates RSA1001
Observable
   .Return(Unit.Default)
   .InvokeCommand(Command);
```

```csharp
// Satisfies RSA1001
Observable
   .Return(Unit.Default)
   .InvokeCommand(this, x => x.Command);
```

The code fix performs this rewrite for you.

## When to suppress warnings

Suppress RSA1001 only where the command instance genuinely cannot be reached through a property
expression on the enclosing type — for example, a command captured from a parameter rather than a
member. Prefer exposing the command as a property and using the expression overload instead of
suppressing.

## Suppress a warning

```csharp
#pragma warning disable RSA1001 // Use expression lambda overload
#pragma warning restore RSA1001
```

```ini
[*.cs]
dotnet_diagnostic.RSA1001.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README for the
`SuppressMessageAttribute` form and when to prefer it over `.editorconfig`.
