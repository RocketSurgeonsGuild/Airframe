# RSA2006: Constant fields should appear before non-constant fields

| Property | Value |
|-|-|
| **Rule ID** | RSA2006 |
| **Category** | Design |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes (shared ordering fix) |
| **StyleCop equivalent** | SA1203 |

## Cause

A `const` field was declared after a non-constant field of the same accessibility.

## Rule description

Constant fields are declared before other fields of the same accessibility. This is one of the
seven RSA2XXX [member-ordering rules](../README.md#member-ordering). RSA2006 never applies to
interfaces or enumerations.

## How to fix violations

Move `const` fields above non-constant fields of the same accessibility, or run the shared ordering
fix (supports Fix All):

```bash
dotnet format analyzers --diagnostics RSA2001,RSA2002,RSA2003,RSA2004,RSA2005,RSA2006,RSA2007
```

## When to suppress warnings

If you already use StyleCop's SA1203 and are not ready to retire it in favor of RSA2006, suppress
one or the other, not both — see [Running alongside StyleCop](../README.md#running-alongside-stylecop).

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Design", "RSA2006:Constant fields should appear before non-constant fields", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA2006 // Constant fields should appear before non-constant fields
#pragma warning restore RSA2006
```

```ini
[*.cs]
dotnet_diagnostic.RSA2006.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README.
