# RSA1007: Use `Invoke()` instead of parentheses for function calls

| Property | Value |
|-|-|
| **Rule ID** | RSA1007 |
| **Category** | Usage |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes |

## Cause

A local delegate/`Func<>`/`Action<>` variable was invoked with call-parentheses syntax
(`func(...)`) instead of `func.Invoke(...)`.

## Rule description

`func()` and `func.Invoke()` compile to the same call, but `func()` reads identically to a regular
method call at the call site, which makes it easy to misread a delegate invocation as a call to a
same-named method or local function. Spelling it `func.Invoke(...)` makes the delegate invocation
visually distinct from an ordinary call.

## How to fix violations

Call `.Invoke(...)` on the delegate instead of using parentheses directly.

```csharp
// Violates RSA1007
var func = () => string.Empty;
var result = func();
```

```csharp
// Satisfies RSA1007
var func = () => string.Empty;
var result = func.Invoke();
```

The code fix performs this rewrite, including for delegates that take parameters.

## When to suppress warnings

Suppress in generated or ported code where matching an external style guide's call syntax outweighs
this convention. Otherwise the fix is a mechanical, low-risk rewrite.

## Suppress a warning

```csharp
#pragma warning disable RSA1007 // Use Invoke method for function calls
#pragma warning restore RSA1007
```

```ini
[*.cs]
dotnet_diagnostic.RSA1007.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README for the
`SuppressMessageAttribute` form and when to prefer it over `.editorconfig`.
