# RSA0008: Do not disable or restore the nullable context in source

| Property | Value |
|-|-|
| **Rule ID** | RSA0008 |
| **Category** | Nullability |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | No |

## Cause

A `#nullable disable` or `#nullable restore` directive appears in source, and its target is
unqualified or explicitly `annotations` - not `warnings` alone.

## Rule description

`#nullable disable` and `#nullable restore` leave the code that follows in an oblivious nullable
context: a reference type there carries no annotation at all, rather than a definite nullable or
non-nullable one. That is a different, and worse, state than either `string` or `string?` - it is
"unknown."

```csharp
// Violates RSA0008
#nullable disable

public class Example
{
    public string Value; // Neither nullable nor guaranteed non-null - unknown.
}
```

Every other rule in this analyzer's `Nullability` category - [RSA0002](RSA0002.md),
[RSA0003](RSA0003.md), [RSA0006](RSA0006.md), [RSA0007](RSA0007.md), and [RSA0009](RSA0009.md) -
reads a type's nullable annotation to decide whether to report. None of them can tell a
legitimately non-nullable reference type apart from one whose annotation state was simply never
tracked, so a disabled or restored context silently defeats every one of them for the rest of the
file - not by reporting the wrong thing, but by having nothing left to read.

**`#nullable disable warnings` and `#nullable restore warnings` are not reported.** Either affects
only whether a warning is produced; the annotation context itself - the half every other rule here
depends on - is untouched.

## How to fix violations

Remove the directive. If a given region genuinely needs oblivious behavior - most often, hand
migration of a legacy file - scope the disabled region as narrowly as possible and prefer enabling
nullable at the project or file level everywhere else, so a `#nullable disable` band is the
exception the reader stops on, not something to search for.

## When to suppress warnings

Suppress in a file mid-migration to nullable reference types, where a `#nullable disable` band is a
deliberate, temporary marker of what's left to convert - not a lasting decision.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Nullability", "RSA0008:Do not disable or restore the nullable context in source", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA0008 // '#nullable {0}' leaves the nullable annotation state of the code that follows unknown; enable nullable at file or project scope instead
#pragma warning restore RSA0008
```

```ini
[*.cs]
dotnet_diagnostic.RSA0008.severity = none
```

See [Suppress a warning](../README.md#suppress-a-warning) in the package README for the
`SuppressMessageAttribute` form and when to prefer it over `.editorconfig`.
