# RSA3002: Lambda expression can be made static

| Property | Value |
|-|-|
| **Rule ID** | RSA3002 |
| **Category** | Performance |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes |

## Cause

A lambda passed to an Rx/DynamicData operator (`Select`, `Where`, `Subscribe`, `WhenAnyValue`,
`Filter`, `AutoRefresh`, a `ReactiveCommand` factory, and similar) captured no local variables or
instance state, but was not marked `static`.

## Rule description

A non-static lambda that doesn't actually capture anything still allocates a closure, because the
compiler can't prove at the call site that it won't need one later. Marking it `static` makes the
compiler enforce that it never captures `this` or a local, which both documents the intent and lets
the runtime skip the closure allocation.

## How to fix violations

Add the `static` modifier to the lambda. The code fix does this for you.

```csharp
// Violates RSA3002
Observable
   .Return(Unit.Default)
   .Select(_ => _staticValue)
   .Subscribe();
```

```csharp
// Satisfies RSA3002
Observable
   .Return(Unit.Default)
   .Select(static _ => _staticValue)
   .Subscribe();
```

## When to suppress warnings

Suppress only where the lambda will need to capture state soon (already scheduled work in the same
change) and marking it `static` now would just be reverted next commit — that's a thin reason;
usually just apply the fix.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Performance", "RSA3002:Lambda expression can be made static", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA3002 // Lambda expression can be made static to prevent accidental variable capture
#pragma warning restore RSA3002
```

```ini
[*.cs]
dotnet_diagnostic.RSA3002.severity = none
```
