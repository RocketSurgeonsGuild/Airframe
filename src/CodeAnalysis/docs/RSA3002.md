# RSA3002: Lambda expression can be made static

| Property | Value |
|-|-|
| **Rule ID** | RSA3002 |
| **Category** | Performance |
| **Default severity** | Warning |
| **Enabled by default** | Yes |
| **Code fix** | Yes |

## Cause

A lambda expression or anonymous method (`delegate { ... }`) can be marked `static` but has not
been. The rule applies to general C# anonymous functions, including LINQ, callbacks and
Rx/DynamicData operators. It requires C# 9 or later and excludes generated code.

## Rule description

Marking an anonymous function `static` makes the compiler reject captures of enclosing instance
state, local variables and parameters. This documents its independence and prevents accidental
captures during later edits. Noncapturing functions can already be cached or emitted without a
closure, so adding `static` does not guarantee a new allocation saving.

The rule checks captures inside the function and references to non-static local functions declared
outside it. Captures in sibling functions do not affect eligibility. A nested function may capture
a parameter or local declared inside the function being marked static; the enclosing function still
has no dependency on external state. Static members, constants and permitted `nameof` references
remain available. Attributed lambdas are currently excluded.

## How to fix violations

Add the `static` modifier. The code fix does this for lambdas and anonymous methods, retaining
comments, parameter lists, bodies and `async` modifiers. It rechecks eligibility before offering
the edit and supports Fix All in a document, project or solution.

```csharp
// Violates RSA3002
Observable
   .Return(Unit.Default)
   .Select(_ => _staticValue)
   .Subscribe();
```

```csharp
// Satisfies RSA3002
Observable
   .Return(Unit.Default)
   .Select(static _ => _staticValue)
   .Subscribe();
```

The same cleanup applies to an anonymous method:

```csharp
Func<int, int> increment = delegate(int value) { return value + 1; };
```

becomes:

```csharp
Func<int, int> increment = static delegate(int value) { return value + 1; };
```

```bash
dotnet format analyzers --diagnostics RSA3002
```

## When to suppress warnings

Suppress only where the lambda will need to capture state soon (already scheduled work in the same
change) and marking it `static` now would just be reverted next commit — that's a thin reason;
usually just apply the fix.

## Suppress a warning

```csharp
[System.Diagnostics.CodeAnalysis.SuppressMessage("Performance", "RSA3002:Lambda expression can be made static", Justification = "<explain why>")]
```

```csharp
#pragma warning disable RSA3002 // Lambda expression can be made static to prevent accidental variable capture
#pragma warning restore RSA3002
```

```ini
[*.cs]
dotnet_diagnostic.RSA3002.severity = none
```
